# Ups.poo.proyecto1.unidad3.AppSorteoLiga
Para este proyecto usaremos el entorno Eclipse para el desarrollo de una aplicación que generará un sorteo aleatorio de 16 equipos para ello la app generará etapas de los octavos de final, los cuartos, las semifinales y la gran final constituyen las etapas sucesivas del torneo.Para avanzar de un nivel a otro, en cada encuentro se designa al vencedor mediante un procedimiento aleatorio (Partido.simularGanador), lo que permite que los equipos seleccionados prosiguan en la competición.No obstante, si se desea otorgar al usuario la facultad de determinar los ganadores, esta implementación requiere únicamente una modificación mínima.
La implementación del método sortearEtapa dentro de la estructura Torneo se fundamenta en un algoritmo recursivo.
Este procedimiento alcanza su condición base cuando el conjunto de equipos restantes se vacía; en ausencia de un oponente válido, el sistema invoca la excepción SorteoInvalidoException.En su iteración recursiva, el algoritmo establece un enfrentamiento entre el equipo inicial y un rival seleccionado aleatoriamente, procediendo a invocar nuevamente la función con la lista remanente.Ante la eventualidad de que dicha rama de ejecución falle, el mecanismo implementa una retrocesión para evaluar y probar con otro rival disponible.
Reglas del sorteo: el algoritmo salta a un rival que sea el mismo equipo y a un partido que ya exista en la etapa (en cualquier orden de local y visitante).
Excepciones propias: NumeroEquiposInvalidoException se lanza si el número de equipos no es potencia de 2 o es menor que 2.
SorteoInvalidoException la lanza el método recursivo.Ambas extienden Exception y pasan el mensaje a super, igual que en tu ejemplo del factorial.
En la gestión de excepciones, el controlador emplea bloques try-catch para interceptar tanto las excepciones inherentes al propio sistema como las de tipo IOException y ClassNotFoundException.
Persistencia: tanto el objeto Torneo como sus entidades asociadas, Equipo y Partido, implementan la interfaz Serializable.
El método guardar del Torneo instancia un ObjectOutputStream junto a un FileOutputStream para escribir los datos en el archivo torneo.ser, mientras que el método carga emplea un ObjectInputStream combinado con un FileInputStream para recuperarlos; estos procesos son invocados por el controlador mediante las opciones 3 y 4 del menú respectivamente.
